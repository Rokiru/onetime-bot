# Working on Dustrivo

- Work in the existing isolated checkout; do not create a worktree unless the user requests one.
- Every completed game update MUST include a newly built APK and a download link. Run `bash scripts/build-apk.sh`, verify success, then copy the delivered APK and SHA-256 into `releases/`.
- Increment the Android version in `app/build.gradle` and `game/AndroidManifest.xml`, and update the filename and expected metadata in `scripts/build-apk.sh`, for each subsequent delivered build.
- This project continues the user-supplied Dustrivo sources. The package is `ru.rokiru.cargo`. Preserve existing vehicle/route IDs, career progress, storage keys, and checkpoint compatibility.
- `ridge25-model.js` owns the separate quick challenge: edition25, career id0 only as a stable constructor/fingerprint identifier, private `ridge:25` road (447 displayed metres), fixed stock ROVER, 1/3 real crates, camp decision at x82, cash-out 100 or finish 250 points per remaining crate plus soft landings. Gas/brake control pitch only when airborne; do not change older physics. `simple25.js`/`simple25.css` own the default two-tab home, one-tap start/retry, minimal trial HUD and inline advanced settings. `ridge25-render.js` draws the actual load, straps, camp and per-load record flags.
- Trial checkpoints use validated optional `ridge25` state and `save.ridgeRun25`; keep `save.activeRun` for story. Per-profile `ridgeRecords25[1/3]` and `ridgeLoad25` must never alter career currency, stats, flags or ghost data. Both modes share the idempotent settled-attempt ledger. Preserve warm solver state during jumps and the camp choice, which freezes physics. Real 0.24 fixtures are in `tests/fixtures/checkpoints-0.24.json`. Test the current default UI with `tests/verify-simple-ui25.cjs`; older UI tests targeting the old home need an explicit Story/legacy fixture.
- Gameplay assets and simulation are in `game/assets/`. Premium rendering is in `premium-render.js`, current interface styling in `expedition.css`, and the drivetrain/UI integration in `expedition-ui.js`.
- New story attempts also pass constructor option `{course: 26}`. `courses26-model.js` adds a versioned terrain modifier over editions20/21/22/23, with deterministic per-route motif sequences, zero-offset/zero-gradient boundaries, guarded added slopes and exact protected interaction geometry. Keep numeric routes/profiles immutable. New collision keys are `course:26:<id>:<baseKey>`. Both generator paths reconstruct independently; `choosePath` applies the modifier before recreating ground/bridge. Never silently upgrade an old checkpoint to the new terrain.
- Optional checkpoint `course26: {edition:26}` reconstructs the same geometry, service refuel (24 vs legacy12), sector boundaries, physics response and fork. On ordinary course26 runs the third star additionally requires every technical sector passed; previews and results must agree. Only course26 runs use immediate requested throttle and airborne-only artificial pitch. New timed road6 has130s, road8 has180s; old limits and canonical urgent110s remain intact. `stats[id].course26` stores new wins/stars/time separately; old career wins still unlock roads and old stats must be preserved. `lightRecords26` keeps generator records separate from earlier terrain; ghosts include an optional course26 discriminator. `courses26-ui.js` integrates existing navigation cues, maps, edge marks and recovery advice without additional overlays. A saved old story run is labelled as previous terrain on home.
- `tests/verify-courses26.cjs` checks all48 stock deliveries with200ms control sampling, warm restores, protected geometry, both branches and old0.25 fixtures. The driver uses only public pedals/transmission/winch/tow actions; it is test code, never ship autoplay. `tests/verify-courses-ui26.cjs` checks real new story paths, liquid/log trips, maps and old-save resume on three phone sizes. Run existing career/mobile/pacing and build regressions as applicable.
- Road 0 new runs use edition 21 (First Light), road 3 uses edition 22 (Water After the Storm), road 4 uses edition 23 (Recovery), and other new runs use edition 20. Preserve base `CP.routes`/profiles and the optional checkpoint `journey`/`expedition`/`waterRun`/`recoveryRun` edition/state. `Drive.id` is the career ID; `Drive.roadId` selects physical geometry. Private `light:pending/ridge/detour` array properties must not change the 48 numeric route/profile entries. Constructor options `{path, powered}` reconstruct edition21 checkpoints. The saved `workshopPowered` flag comes only from a successful new generator delivery, not old route-0 wins.
- `first-light-model.js` owns the branch and generator physics; `first-light-ui.js`/`first-light-render.js` integrate the story and workshop. Keep analog motor enable state boolean so checkpoints remain valid during partial throttle. Legacy 0.20 checkpoint fixtures are in `tests/fixtures/checkpoints-0.20.json`.
- `water-run-model.js` owns the private `water:22` road and pump state. Preserve original numeric road 3/profile so old saves restore. The 3-second installation selects cargo index 0; the cabinet must remain aboard until the final station. `villageWater` is set only by a successful edition22 delivery. `{support: true}` enables the mid-route repair/refuel crew when `workshopPowered` is saved. `water-run-ui.js`/`water-run-render.js` own its navigation, village view and cached architecture.
- `recovery-model.js` owns the private `recovery:23` road, physical van and RopeJoint. Preserve the original numeric road 4 express contract for old checkpoints. RopeJoint uses localAnchorA/B, not the DistanceJoint two-world-anchor overload. `recoveryRun.tow` stores hitch, support, health, overload and damage velocity history; restore creates the matching rope before restoring solver state. Keep both vehicles stopped for delivery, retain the tool case, require a deliberate unhook in the bay, and hold the brake there without automatic reverse. Only a new edition23 win sets `villageRescue`; this grants three ordinary winch charges in subsequent new runs, never retroactively changes a suspended run. `recovery-ui.js`/`recovery-render.js` own cues, the two-vehicle camera integration and village action. Real 0.22 checkpoint fixtures are in `tests/fixtures/checkpoints-0.22.json`.
- `dispatch-terms24.js` owns the optional fixed edition24 urgent agreement on road 1, edition20. Keep its canonical 110-second deadline, +180 for all four crates on time and late fee up to 80 capped by cargo payment, never collected coins. Late urgent deliveries cannot earn the third star. Ordinary and older checkpoints have no `dispatchTerms` and retain original payouts/physics. Restore the optional agreement from validated checkpoint data; do not change numeric route entries or the old fingerprint.
- `restoration24.js` derives the nine-stage story plan from existing flags/stats. First three stages require actual `workshopPowered`/`villageWater`/`villageRescue`, never infer them from old wins. `opening24.js` integrates home goals, the scrollable plan with pinned actions, free preparations, explicit upgrade purchases, the optional fourth-run agreement and result impact. Preparation must not mutate a suspended run. The first edition21 lesson uses the existing four coach steps (three practiced actions plus acknowledgement); incomplete teaching survives a fork and checkpoint reload.
- `depot-art20.js` caches roadside architecture; `journey20.js` renders mission maps and missed-stop/sector cues. Mini-map rendering is separate from text HUD updates.
- Run relevant physics, UI, delivery, checkpoint and storage tests for changes. The current road count is 48; older tests have historical fixtures. Test fixtures must select their intended career/test profile explicitly.
- Android builds use the pinned tools in `.tools/` and `scripts/gradle.py` for proxy and CA trust. Never disable TLS or archive checksum verification.
- The original development signing key supplied in the archive is retained under ignored `.tools/dustrivo-signing/`. Never commit it, passwords or `signing.properties`. A fresh clone without that key uses a different debug key and cannot update the supplied older development APK in place.
- `scripts/build-apk.sh` uses a signed, non-debuggable Release build when the retained signing configuration exists; otherwise it falls back to a separate debug development build. `DUSTRIVO_BUILD_TYPE=release` requires the retained signing configuration and verifies the original public signer digest. Never silently generate a replacement key for delivered updates. Real-device validation, ownership/backup of the permanent signing key and human playtests remain prerequisites for a RuStore publication.
- Keep the game offline. Do not add ads, analytics, external resources or Internet permission without a user request.
- Do not restore the discarded Iskra project. Localhost/browser servers are for internal verification and are not user download links.
